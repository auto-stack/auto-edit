## 1. 内核 rope 化（单写者版）

- **诉求**：`CodeEditorCore`（`crates/auto-lang/src/ui/code_editor/core/mod.rs`）
  文档缓冲从行数组形态迁到 rope + 摘要（叶存文本块，节点缓存长度/行数/
  点-偏移换算，O(log n) 编辑与定位）。
- **明确不要的**：协作基因——无 OT/CRDT/多编辑流合并。**单写者模型**：
  主线程写，后台任务（解析/搜索/diff/保存）只读快照隔离。copy-on-write
  的动机仅为快照，非多人并发。
- **动机（预算门控）**：auto-edit 战略 §2.1 解锁条件列——100 MB 文本
  打开 ≤1 s、1 GB 可打开（分块/mmap）、大文件满帧滚动、空闲内存 ≤60 MB，
  在 rope 前架构性不可达（已裁定：rope 前禁对该路径调优）。
- **验收形态建议**：缓冲编辑 API 复杂度文档化（编辑/定位 O(log n)）；
  100 MB 文本打开+滚动冒烟可跑；现有 code_editor_* 内建语义零回归
  （auto-edit 矩阵为下游验收面）。

## 2. 统一 delta 协议（编辑事件增量化）

- **诉求**：code_editor 编辑事件从"整文本回读"改为**区间增量**（delta）：
  人击键、agent 结构化写（区间替换/插入/删除）、undo/redo 走同一条增量
  事件流——人与 agent 的写在内核层无差别。
- **现象（下游现状证据）**：auto-edit `specs/auto-edit/src/front/editor_store.at`
  五处以 `code_editor_text(key)` 全量回读维护 `.tabs[i].src` 字符串镜像
  （CtxCut/ActUndo/ActRedo/ActCut/ActPaste，约 L229/350/359/376/391）；
  每击键级操作复制全文，对大文件是结构性死罪。
- **期望形态**：`code_editor_delta(key) -> {start,end,replacement}` 事件
  或等价订阅面；配套 agent 结构化写端点（见 §3 同期的 back 面扩容）。
  auto-edit 侧 store 去文本化（PLAN-005 候选）以本项为前置。
